# AI usage log

Tools: Claude Code wrote the first draft of most files; I reviewed, ran everything, and the entries below are the places where the generated code or tests were wrong and got changed.

| # | Situation / what the AI produced | What I changed | Why |
|---|---|---|---|
| 1 | `NoteCreate.text` with `min_length=1`, and the route calling `.strip()` after validation. The first test for it accepted either 201 or 422. | Strip whitespace inside the schema (`StringConstraints(strip_whitespace=True, min_length=1)`) and made the test assert exactly 422. | A note of `"   "` passed validation and was stored as an empty string. The either-or assertion hid that bug; a test that cannot fail is not a test. |
| 2 | A word-quality heuristic in `sanitize.py` that treated words with digits (`EC2`, `S3`, `Python3`) as garbage. | Found it when a generated test resume failed the gate, then deleted the heuristic (and a repetition check) entirely. | Length plus letter-ratio already catches the real garbled case; the extra checks guarded inputs no recruiter would paste, and the first one rejected legitimate tech resumes. |
| 3 | When I ran my own injection test (Chris Patel) against the real model, 3 of 4 runs failed with "invalid summary". I printed the raw output which showed the model had resisted the injection, but wrote a 215 character flag explaining it, and `model_validate` rejected the whole summary because flags are limited to 200 characters. I also had Claude rerun the same process to make sure it prints the same error. I then asked the AI to truncate over-long flags, highlights and skills instead of rejecting, while still rejecting structural errors. | Kept its approach of reading the limits from the schema instead of hard-coding 200/40/240. Checked the new test fails with the fix removed. Left `headline` out of truncation because the headline should be one sentence, so a 200+ character headline is a real error worth rejecting. | The strict limit punished the exact case the feature exists for, which is that injection resumes make the model write longer flags. A safe, correct summary was being thrown away over the length of one note. |
| 4 | On the Sam Whitfield resume, the real model flagged the injection itself, but the recruiter saw two warning notes. The code added its own note unless an existing flag contained the word "instruction", and the model had written "instructing". I asked the AI to add our note only when our regex caught an injection the model missed, while still forcing `injection_detected=true` whenever the regex matches, with a test reproducing the Sam case. | Its first version did exactly that, but left a gap it pointed out in review which was if the model set `injection_detected=true` with no flags, the recruiter would see the warning banner with nothing explaining it. I decided that case should be covered and asked for it, with its own test. Ran both new tests with the fix removed and confirmed they fail. | Matching on a word depends on how the model happens to phrase things, so the fix uses facts we control (did our regex match, did the model detect it) instead. Trusting the model's own note avoids repeating the warning, and the fallback means the banner is never left unexplained. |
| 5 | The Alex Roy seed resume (a long block of garbled PDF bytes) was rejected with "Resume text is too short to summarise", because `quality_problem()` checked the letter count before checking for garbled text. I asked the AI to run the garbled check first, keep both cases rejected before any model call, and update the existing test to check the message for each case. | The AI also added a guard I hadn't asked for (`if non_space and ...`). I checked why, and it said with the checks swapped, an empty or whitespace-only resume that has zero non-space characters, the ratio check would divide by zero and crash with a 500 instead of a clean 422. I removed the guard temporarily, saw the empty-resume test cases fail, and kept it. | Swapping two checks looked like a two-line change but hid a crash. An unrequested change from an AI tool needs checking before accepting, not blind trust and here the check showed it was necessary. Also confirmed only the message changed and all five real seed resumes still pass or fail the gate exactly as before. |
